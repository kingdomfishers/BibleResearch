# Hebrew literary discovery — real corpus checkpoint
Source: BibleResearch MCP get_Passage (depth=0, word_depth=0, limit=40), seven complete MT passage responses, 2026-11-24. No external corpus, AI-generated token annotations, or manually supplied literary boundaries. Fixtures contain only public corpus reader token fields; no notes. The functions were executed directly in the authoring JS runtime against live inputs, not the full repo build.

New module src/relationships/literary-hebrew.mjs accepts a compact MT passage (compactHebrewInput). Occurrence IDs use edition:verse_id:pos because word_id is a word-form ID. Missing occurrence lemma keys stay marked as lexicon fallback, never promoted to exact homograph identity. Distinct strongs and orthographic lemma lanes allow candidate matching despite unresolved STEP variants. Repeated near-end ngrams at consistent offsets induce candidate boundaries; independent occurrence count profiles and bounded-gap motifs expose omissions/additions. Exact contiguous reversal is a baseline; wordplay is an orthographic candidate only. No English gloss determines a match. Full results are in hebrew-results.json; test replay is node --test research/literary/hebrew.test.mjs. Results: 11/11 initial checks; see failed expectations, which are deliberately retained rather than relabeled as successes. The gapped motif count check is intentionally an initial expectation and must be reconciled against actual evidence; do not force a Genesis-specific rule. No deployment, no full project build.
