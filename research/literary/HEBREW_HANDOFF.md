# Hebrew literary discovery — real corpus checkpoint
Source: BibleResearch MCP get_Passage (depth=0, word_depth=0, limit=40), seven complete MT passage responses, 2026-11-24. No external corpus, AI-generated token annotations, or manually supplied literary boundaries. Fixtures contain only public corpus reader token fields; no notes. The functions were executed directly in the authoring JS runtime against live inputs, not the full repo build.

New module src/relationships/literary-hebrew.mjs accepts a compact MT passage (compactHebrewInput). Occurrence IDs use edition:verse_id:pos because word_id is a word-form ID. Missing occurrence lemma keys stay marked as lexicon fallback, never promoted to exact homograph identity. Distinct strongs and orthographic lemma lanes allow candidate matching despite unresolved STEP variants. Repeated near-end ngrams at consistent offsets induce candidate boundaries; independent occurrence count profiles and bounded-gap motifs expose omissions/additions. Exact contiguous reversal is a baseline; wordplay is an orthographic candidate only. No English gloss determines a match. Full results are in hebrew-results.json; test replay is node --test research/literary/hebrew.test.mjs. Results: 11/11 initial checks; see failed expectations, which are deliberately retained rather than relabeled as successes. The observed gapped evaluation count is 1,0,2,1,1,2 (day six has two evaluations). No deployment, no full project build.

## Shared-core integration checkpoint
Added literary-hebrew-alignment.mjs. It directly imports the prior induceTemplate and discoverChiasms algorithms, selects nonoverlapping motif events, links actual evidence, builds verified MACULA predicate-role streams when coverage is complete, and detects morphology and source syntax variations. The grammar fixture comes from four real grammar_search calls covering Genesis 1:1–2:3 (the service caps each range to ten verses). 8/8 additional checks passed on actual repository module source executed in a JS runtime with the captured corpus fixture. Failed checks, if any, are retained in the benchmark. No full project build or deployment. The 11 initial and 8 additional tests are development checks, not evidence of global precision. Both base and aligned outputs are in hebrew-results.json. Run node --test research/literary/hebrew.test.mjs.

Limitations: only the Genesis fixture includes MACULA annotations; no LXX yet. Some lexical events use broad Strong's or orthographic keys. Motif selection is greedy; the best terminal-anchor segmentation is still only a hypothesis (Psalm 107 thanksgiving refrains precede the true final response). The grammar template uses source predicates, not inferred semantic equivalence. The first Genesis unit includes the prologue; improve boundary inference. The Sabbath is an unmatched tail, not an automatically proven seventh aligned unit. Modifier labels are source adjective-adverb syntax, not automatically interpreted as degree. The source grammar code records first-person plural; the engine flags the unusual person but does not infer theology. Integrate Worker/UI/MCP using the existing runtime routing and tune on held-out data.
